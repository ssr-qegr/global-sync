1. vercel-labs/agent-browser

面向 AI Agent 的浏览器自动化 CLI，把打开页面、读页面、点击、填写、等待、调试与会话管理全部收敛成可组合命令

TOP 1
🌐 Browser Automation🦀 Rust Native CLI🧭 Snapshot Ref 机制🔌 MCP Server🔐 Session / Auth 持久化

项目详细介绍：Agent Browser 是 Vercel Labs 开源的浏览器自动化 CLI，目标非常清晰：给 AI Agent 一个足够稳定、足够细粒度的网页操作执行层。它不是只暴露几个 Playwright 包装命令，而是把浏览器中的核心动作拆成了大量可被模型组合的能力，例如 open、read、snapshot、click、fill、wait、screenshot、network、console、react、a11y、mcp 等。它最有代表性的设计是通过可引用的元素标号和稳定会话，让模型不必每次都靠脆弱的 CSS 选择器猜页面，而是可以围绕“可读、可验证、可重试”的页面状态来行动。

技术亮点

  • Snapshot 引用机制很适合 AI：通过无障碍树快照和像 @e2 这样的元素引用，让模型基于页面结构执行动作，比单纯拼 selector 更稳。
  • 读页面能力不只看 DOM：read 既能直接抓 URL 内容，也能读当前活跃标签页的渲染结果，还考虑到 llms.txt、Markdown 返回和 HTML 可读化场景。
  • 调试和观测能力完整：除了交互命令，还内置 network、HAR、console、errors、trace、profiler、React 组件树、Web Vitals 和 a11y 审计，方便把“能执行”进一步推进到“能排查”。
  • MCP 支持直接到位：项目自带 MCP Server，并把常用浏览器动作映射成 typed tools，便于被外部 Agent 框架直接接入。
  • 登录态与会话管理实用：支持 profile、state、session、auth 保存与恢复，适合真实网站上的连续任务，而不是一次性演示脚本。

使用场景

  • Browser Agent 原型验证：如果你想验证“模型能不能在网页里完成真实任务”，它非常适合作为第一层执行底座。
  • 网页自动化与数据采集：适合做需要导航、点击、填写表单、读取页面内容、保存截图的自动化流程。
  • 前端问题排查：当你要结合 DOM、控制台、请求链路、性能指标一起定位页面问题时，这套命令行能力很有价值。
  • 带登录态的网站操作：对需要复用浏览器状态、导入认证信息或长期保持会话的场景尤其友好。

为什么今天推荐它

  • 很多人会聊 Browser Agent，但真正值得学的是它如何把“看见页面”变成“稳定操作页面”的工程实现。
  • Agent Browser 把执行、观测、调试、认证和会话都铺开了，很适合工程师反向理解 Agent 产品底座应该长什么样。
  • 对技术成长来说，它能帮助你把网页自动化、MCP、可观测性和 AI 执行控制这几件事连成一张图。

2. HKUDS/nanobot

超轻量、自托管的个人 AI Agent 框架，把 WebUI、终端、聊天渠道、工具、记忆、自动化和 OpenAI-Compatible API 做成一个可长期运行的整体

TOP 2
🤖 Self-Hosted Agent🧠 Memory / Automation🪟 WebUI + Terminal🔌 MCP / OpenAI-Compatible🐍 Python

项目详细介绍：Nanobot 是一个很有“系统感”的个人 AI Agent 开源项目。它的定位不是单点聊天机器人，而是一个可以长期运行、可自托管、能接入多种渠道的 Agent Runtime。官方 README 直接给出了它的核心组合：WebUI、终端、聊天应用接入、工具调用、长期记忆、MCP 集成、模型路由、多智能体委派、定时自动化，以及 OpenAI-Compatible API。换句话说，它想解决的不是“怎么再包一层 LLM 对话”，而是“怎么让个人 Agent 真正成为一个持续在线、可配置、可扩展、可部署的软件系统”。

技术亮点

  • 核心保持轻量：项目强调 small, readable core，把复杂能力尽量挂接在清晰的 Agent 主循环周围，阅读和二次扩展门槛相对更低。
  • 渠道覆盖完整：除了 WebUI 和终端，还能接 Telegram、Discord、Slack、WeChat、Feishu、Email、Mattermost 等，适合做真正的“随处可用 Agent”。
  • 运行时能力很全：包含长程目标、定时自动化、工具调用、长期记忆、子 Agent 委派、模型切换和配置热更新，不只是一个聊天入口。
  • 模型与部署自由度高：支持 OpenAI-Compatible API、本地模型、自托管部署、Docker、Linux service、macOS LaunchAgent 等多种运行方式。
  • WebUI 做得很像工作台：可以在浏览器里看 topic、模型、workspace、工具调用、文件改动、生成产物和自动化配置，适合长期使用而不只是一次运行。

使用场景

  • 个人 AI 工作台：如果你希望把自己的 AI 助手真正跑起来，而不是每次打开一个新聊天窗口，Nanobot 很有参考价值。
  • 自托管自动化助手：适合处理日常巡检、内容整理、定时任务、工具编排和多渠道通知等持续性工作。
  • Agent 框架学习：它很适合拿来理解一个完整 Agent Runtime 通常需要哪些部件，例如记忆、工具、模型路由、自动化和 UI。
  • 内部工具与集成：如果你想把个人 Agent 进一步接到聊天应用、API 或本地工具链里，它提供了比较完整的延展路径。

为什么今天推荐它

  • 现在很多 Agent 项目强调“效果演示”，而 Nanobot 更像是在认真回答“一个可长期运行的个人 Agent 应该怎么落地”。
  • 它把 UI、运行时、自动化、模型和接入层都连了起来，适合开发者从整体上理解 Agent 产品化。
  • 对技术成长来说，它很适合拿来补齐从“会用模型”到“会搭建 Agent 系统”之间的那一层工程能力。
