1. TencentCloud/TencentDB-Agent-Memory

面向 AI Agent 团队的分层记忆中枢：把对话、文档、代码和经验沉淀成可治理、可共享、可装配的长期资产

TOP 1
🧠 Chat Memory⚡ Skill Library📖 Wiki🔗 CodeGraph👥 Team Memory Hub🔐 ACL / Loadout

项目详细介绍：TencentDB Agent Memory 可以理解成一套专门为 Agent 团队打造的“经验资产化系统”。它不只保存聊天记录，而是把对话、文档、代码和任务执行过程转换成四类可复用的 Memory Asset：Chat Memory、Skill、Wiki 和 CodeGraph。这样一来，Agent 下次执行时不需要重新认识用户、重新读一遍文档、重新摸索代码结构，而是可以直接继承上一次沉淀下来的有效经验。官方仓库还特别强调它支持跨 Agent、跨框架复用，能把已有代码仓、文档和历史会话导入系统，降低新 Agent 的冷启动成本。

技术亮点

  • 四类记忆资产设计很完整：Chat Memory 记住偏好、事实和决策，Skill 沉淀可执行经验，Wiki 组织文档知识，CodeGraph 建立代码符号、调用关系和影响范围。
  • 分层记忆而不是平铺摘要：官方把会话分成 L0 对话、L1 原子信息、L2 场景知识、L3 Persona，让长期任务里的信息能逐层蒸馏，不是简单压成一段摘要。
  • 很适合多 Agent 协作：同一团队里的不同 Agent 可以装配不同资产，比如 Builder 重点挂 Product Wiki 和 CodeGraph，Reviewer 重点挂历史事故记忆和发布清单 Skill。
  • 知识与代码一起进入记忆层：Wiki 负责把文档结构化，CodeGraph 负责把代码索引成可搜索、可做影响分析的资产，这比传统只做文本 RAG 更适合研发场景。
  • 治理能力做得比较重：Memory Hub 不只是展示面板，还支持所有权、版本、状态、可见性和 ACL 绑定，方便把团队经验真正管起来。

使用场景

  • 长期运行的研发 Agent：适合需要跨会话保留偏好、约束、任务上下文和阶段结论的开发助手或研究助手。
  • 多 Agent 协作团队：当你有 Scout、Builder、Reviewer 这类角色分工时，可以给不同 Agent 装配不同记忆资产。
  • 项目知识沉淀：可以把代码仓、设计文档、历史会话导入系统，减少每次开新任务都要重新学习项目的成本。
  • 代码理解和变更评估：CodeGraph 适合做调用链分析、影响范围分析，帮助 Agent 在改代码前先理解后果。

为什么今天推荐它

  • 很多团队已经开始做 Agent，但真正难的是怎么把经验沉淀下来，而不是每次都从零开始。
  • 这个项目最值得看的不是“记忆”两个字，而是它把记忆、知识、代码和权限治理放到同一套资产模型里。
  • 如果你关心的是 AI 工程化长期价值，而不是一次性 Demo，这个仓库非常有参考意义。

2. NVIDIA/SkillSpector

面向 AI Agent Skill 的安全扫描器：在安装前识别漏洞、恶意模式、越权行为与供应链风险

TOP 2
🛡️ Skill Security🔍 Static Analysis🧠 Semantic Analysis📦 Supply Chain📄 SARIF / JSON🔌 MCP Ready

项目详细介绍：SkillSpector 是 NVIDIA 开源的一套 Agent Skill 安全扫描工具，目标很直接：在你安装一个 Skill 或 MCP 能力之前，先回答“它到底安不安全”。官方 README 把它定义为 AI agent skills 的安全扫描器，支持扫描 Git 仓库、URL、zip 包、目录和单文件；官方文档则进一步说明，它既可以做默认的快速静态检查，也能加入可选的 LLM 语义分析，用来判断描述与行为是否一致、是否存在隐藏触发条件或权限声明不充分等问题。对于越来越依赖第三方 Skill 和工具生态的 Agent 系统来说，这类前置安全检查会越来越重要。

技术亮点

  • 覆盖面足够广：官方说明它覆盖 68 类漏洞模式、17 个风险类别，包含 prompt injection、data exfiltration、privilege escalation、memory poisoning、MCP least privilege 和 MCP tool poisoning 等典型问题。
  • 双阶段分析思路很实用：先做快速静态分析，再按需加语义分析，既能兼顾速度，也能补足“描述和实际行为不一致”这类更隐蔽的风险。
  • 供应链风险纳入默认流程：它会查询 OSV.dev 做依赖漏洞检查，网络不可用时还有离线 fallback，这对 Skill 生态很关键。
  • 输出格式适合工程接入：除了终端输出，还支持 JSON、Markdown、SARIF，方便接入 CI、代码扫描平台或审核流程。
  • 可以做安装前闸门：官方 triage policy 明确建议把扫描结果作为 release gate 或 install gate，而不是只看一份报告就结束。

使用场景

  • 引入第三方 Skill 前审查：当团队要安装来自外部社区的 Skill、MCP Server 或自动化脚本时，可以先做风险扫描。
  • 企业内部 Skill 发布门禁：适合把扫描结果纳入内部 Skill 发布流程，提前拦截隐藏指令、权限过宽或依赖漏洞问题。
  • Agent 平台治理：如果你在做 Agent 市场、Skill 广场或内部插件中心，SkillSpector 能作为统一的安全检查底座。
  • 安全学习与规则建设：它的风险分类本身也很适合帮助团队建立对 Agent Skill 风险面的系统认知。

为什么今天推荐它

  • Agent 生态越繁荣，安装第三方 Skill 的风险就越大，很多问题不是运行后才发现，而是安装前就该拦下来。
  • SkillSpector 值得看的不是“扫漏洞”本身，而是它把 Agent Skill 的风险建模、语义检查和供应链检查组合成了一条实际可落地的流程。
  • 如果你正在做 MCP、Skill 平台、企业 Agent 接入治理，这个项目非常值得收藏和拆读。
