2. tirth8205/code-review-graph

面向 MCP 和 CLI 的本地代码智能图谱，让 AI 只读取真正相关的上下文，减少 review 与大仓理解成本

TOP 2
🕸️ Code Graph🔌 MCP Ready🧪 Review Context🧭 Local-firstCLI / VS Code

项目详细介绍：code-review-graph 的问题意识非常强：AI coding 工具在 review 和大型仓库任务里，经常会反复读取大量无关代码，既费 token，也费时间。这个项目的做法，是在本地构建一个持久化的代码智能图谱，帮助 MCP 和 CLI 工具只抓取真正相关的文件、符号和依赖关系。官方仓库对定位写得很直接，它不是一般意义上的代码搜索器，而是想把 review、变更影响分析和大仓上下文选择这件事做成一个“AI 可消费”的能力层。

技术亮点

  • 本地优先的代码图谱：把代码库结构和关系长期保存在本地，不必每次任务都从头扫描全仓。
  • 为 MCP 与 CLI 设计：从仓库标题和描述就能看出，它天然面向 Agent 工具链，而不是只做给人看的静态分析结果。
  • 上下文压缩思路明确：核心目标不是“分析得更多”，而是“让 AI 少看无关内容，只看真正相关部分”，这对大仓场景尤其重要。
  • 覆盖 review 工作流：README 直接强调 review tasks 和 large-repo workflows，说明它面向的是高频真实研发场景。
  • 有扩展形态：项目还提供 VS Code 方向的能力，说明其价值不仅限于命令行，还能继续接入图形化开发环境。

使用场景

  • 代码评审提效：在 Review 之前快速定位变更相关代码、依赖链路和潜在影响面。
  • 大仓理解：面对复杂 monorepo 时，帮助 AI 和开发者更快缩小阅读范围。
  • Agent 工具链增强：如果你在做 MCP Server、CLI Agent 或内部 AI coding 平台，这类项目很适合作为基础设施参考。
  • 变更影响分析：在重构、改接口或处理线上问题时，更适合先看 blast radius，再决定检查范围。

为什么今天推荐它

  • 它抓住了 AI Coding 当前一个非常现实的瓶颈：不是模型不会写，而是上下文经常喂错、喂多、喂得太慢。
  • 如果你想提升自己在大仓分析、代码评审、工程工具方向的理解，这类项目比单纯模型调用更有长期价值。
  • 它也很适合启发你思考：未来研发效能平台的核心竞争力，可能就在“如何更聪明地组织上下文”。
